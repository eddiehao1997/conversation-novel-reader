# 对话气泡：设计说明（POC）

## 目标

把小说里的人物对话显示成对话框，让读者一眼就能分清是谁在说话：

- 每个角色有自己的**颜色**和**头像**；
- 同一本书里，同一个角色在**所有章节、每次打开、每台设备上**都用同一套颜色和头像；
- 识别不准时，读者可以一键修正，修正结果对整本书生效。

## 整体方案

```
txt ─▶ 分章（已有） ─▶ ① 角色表 buildCast（Web Worker，每本书只算一次，结果缓存到 IndexedDB）
                       │      名字 / 别名 / 说话次数 / 颜色 / 头像
                       ▼
            每章渲染时 ② attributeChapter（主线程，每章约 1ms）
                       │      每句对话 → 说话人 + 置信度
                       ▼
            ③ 读者修正（按书保存）  ─▶  ④ 渲染成气泡
```

整个流程在本地完成，不需要联网，也不需要 API key。代码在 `dialogue.js`（引擎）、`dialogue-worker.js`（后台分析）和 `index.html`（界面）。

### ① 角色表：从书里自己找出人物

1. **找“说话人位置”**：只统计书中明确标注说话人的地方。例如「X想了想，开口道：」之后紧跟一段引语，或者「“……”X笑道。」。
2. **切出名字**：说话人位置的开头几个字一般是“名字 + 动作”（例如「克莱恩笑着说道」）。用**右分支熵**判断名字在哪里结束：一个真正的名字后面会接各种不同的字（笑/看/说/点…）；「克莱」后面几乎总是「恩」，所以不是名字的结尾。
3. **过滤普通词**：用 jieba 词典里约 2.4 万个常用词（非人名词性，MIT 许可）去掉「看着」「过了」「语气」这类词，再用一些片段规则（如「X了」「的X」「边X」）去掉词组碎片。
4. **合并别名**：
   - 「伦纳德·米切尔」→「伦纳德」（全名去掉姓）；
   - 「管家瓦尔特」→「瓦尔特」（头衔 + 名字）；
   - 但「德尼尔」和「尼尔」不合并，因为前缀不是头衔，他们是不同的人。
5. **代号也算角色**：像「“世界”沙哑笑道」这种用引号括起来的代号，也会被识别成角色。
6. **排序**：按说话次数排序。

### ② 每句话是谁说的

先区分**对话**和**引用词**：「据说“愚者”先生……」里的“愚者”不是对话。判断依据：引语的位置（段首、冒号后），以及引语末尾有没有标点。

然后为每句对话找说话人，并标出置信度。

**跨段长对话**：一个人连续说多段话时，每段以 “ 开头，只有最后一段才闭合。这些段落按同一段话处理，并沿用第一段的说话人。全书约有 3,100 处，共 8,800 段。

| 置信度 | 规则 | 示例 |
|---|---|---|
| 明确 explicit | 引语前后有说话动词，且主语是角色 | 「X开口道：“…”」「“…”X问。」「就听见莎伦…说道」 |
| 上下文 context | 引语紧接着角色动作；同一段里的续说 | 「“…”X放下刀叉」 |
| 推测 inferred | 代词按同一句里前面的名字或最近作主语的角色推断（会排除「等到X…，他」这类从句里的名字，并区分性别）；快速你来我往时轮流发言 | 「这次回答的是马里奇，他详细说道：」 |
| 未知 | 没有足够线索 | — |

#### 评测

评测集为 `tests/labels-guimi.json`：从《诡秘之主》中均匀选取 6 章，逐句人工标注了 232 句。文件只存位置和人名，不含正文。运行方法：

```bash
node tools/eval.mjs 诡秘之主.txt tests/labels-guimi.json [--ollama qwen2.5:7b] [--verbose]
```

| 来源 | v1（POC） | v4（当前） |
|---|---|---|
| 明确 | 89% | **99%** |
| 上下文 | 90% | 89% |
| 推测 | 41% | **80%** |
| 有名字的句子 | 81% | **94%** |
| 整体（含该显示「未知」的） | 71% | **82%** |

剩下的错误大多需要真正理解情节：读日记、脑海里的声音、变成麻雀的阿蒙、念信等。这部分交给本地模型。

全书统计（v4）：37,436 句对话中，明确 43%、上下文 21%、推测 15%，共 79% 标出了说话人。全书分析在笔记本上约 1 秒，手机上几秒；之后每章渲染约 1 毫秒。

### 心理活动

这本书写心理活动时不加引号，而是在想法后面跟一句标注：

- 「对！一定是队长赶到附近了！他心中一喜，…」
- 「我知道了未来的方向……她愉快地在心里补充了一句。」
- 「克莱恩心想：…」

识别规则：在 ……／？／！ 处断开（如果是句号，要求想法里有「我」），断开后的下一个分句要以人物（角色名或他／她／祂）开头，并在 16 个字以内出现「心想、暗自、在心里、腹诽、吐槽、念头、思绪……」这类词。想法里的引号术语（如“正义”小姐）会保留在想法内。

全书共识别出约 1,680 处心理活动，其中约 88% 有明确的人名标注。代词按最近一个作主语的角色推断，并标为「推测」。心理活动**不做特殊排版**，仍按正文显示；识别结果只用来追踪“当前在想/在说的人”，帮助判断后面对话的说话人。

没有任何标注的自由间接引语（例如单独一段「他怎么确认的？」）目前仍按旁白显示，这类情况需要模型来判断。

### ③ 一致性：为什么颜色不会变

- **颜色和头像只由书的内容决定。** 角色按说话次数排名：前 16 名依次使用 16 个间隔开的色相，之后的角色用名字的哈希值计算色相（黄金角分布）。头像是名字的第一个字，再加 4 种形状之一（圆形 / 圆角方形 / 双圈 / 角标），首字相同的角色也能区分开。
- 同一个 txt 文件在任何设备上算出的角色表完全相同，所以颜色在各章节、每次打开、各设备之间都一致。脚本验证过全书 1,402 章、235 个角色，没有一处颜色不一致。
- 分析结果缓存在 IndexedDB 里，按「书 ID + 引擎版本」保存。引擎升级时会重新计算。

### ④ 本地模型复核（Ollama）

规则拿不准的句子（上下文、推测、未知）会交给电脑上的本地模型重新判断，不联网，代码在 `llm.js`。

- **怎么问**：按段落组成约 2,600 字的片段。片段里，规则已确定的句子标成「【克莱恩】“…”」作为线索，需要判断的句子标成「【L3】“…”」。
- **只能从候选里选**：候选名单包括本段出现的角色、附近的说话人和主要角色。Ollama 的 `format` 参数用 JSON Schema 的 `enum` 限定答案，只能是候选名字或「未知」，**模型不可能编出新角色**，颜色和头像保持一致。
- **优先级**：读者标注 > 规则·明确 > 本地模型 > 规则·上下文/推测 > 未知。模型的答案会作为已确定的事实重新跑一遍规则，所以前后的代词和轮流判断会跟着更新。
- **调度和缓存**：打开一章时复核本章，并预读下一章，同一时间只发一个请求。结果存在 IndexedDB 里，按 书 ID + 引擎版本 + 模型 + 章节 + 本章标注 保存，所以本章标注变化后会重新复核。
- **出错时**：连接失败或没有安装模型时提示一次，不会反复重试，并退回只用规则。
- **启用方法**：
  1. 在电脑上安装 Ollama，执行 `ollama pull qwen2.5:7b`；
  2. 用 `OLLAMA_ORIGINS="https://eddiehao1997.github.io,null" ollama serve` 启动，其中 null 对应双击打开的单文件版；
  3. 在阅读器里依次点 Aa → 对话气泡 → 本地模型复核，然后测试连接。
- 手机和 claude.ai 链接版访问不了本机的 Ollama，会自动只用规则。

### ⑤ 读者标注与验证

- **修正**：点头像或名字。可以选只改这一句，或者本书所有「X」都改（相当于合并角色）。
- **确认**：带「推测」或「模型」标记的气泡旁有 ✓，点一下就记为正确。
- **记录**：每次修正或确认，都会同时记下当时规则和模型各自给出的答案（`meta`）。「角色与标注 → 准确率」用这些记录算出各来源在这本书上的准确率。
- **自动停用**：某个来源在 20 句以上的标注中准确率低于 60% 时，它的猜测自动改为显示「未知」。
- **前后联动**：标注作为确定的事实传回规则引擎（`anchors`），本章前后的判断会一起更新，模型也会重新复核这一章。
- **导出/导入**：标注可以导出为 JSON，格式和 `tests/labels-guimi.json` 相同，可以直接用于 `tools/eval.mjs`，也可以在另一台设备导入。
- 标注按书保存在本机，键名为 `dlg_<书ID>`。

### 显示

- 气泡的颜色用 `oklch(L C 色相)` 计算，`L/C` 跟随当前主题（白 / 羊皮纸 / 护眼绿 / 夜间），所以各主题下都清晰易读。
- 推测的对话用**虚线边框**并标「推测」，模型给出的标「模型」，读者修正过的标「已修正」，未知说话人用灰色头像「?」。
- 气泡段落里的旁白和心理活动按正文样式显示，不加任何特殊格式。一个人跨段连续说话时，不重复显示头像和名字。
- 每个段落仍然是一个顶层元素（`.para`），所以段落级的阅读进度、跨设备同步、改字号保持位置等功能都不受影响。开关对话气泡时，也会停在同一段。

## 已知限制

- **单字名字**只有在书里也出现过「X·全名」时才会识别（例如「休 / 休·迪尔查」）。
- **没有固定名字的人物**（「那中老年男子」「警长」）显示为未知，模型也只能回答未知。
- **读日记、念信、脑海里的声音**等情况，单靠规则判断不了，要靠本地模型或读者标注。
- **两人严格轮流**的规则试过后撤回了：它会把连续的日记、祷文错判成两人对话（全书误改了 288 句）。
- 现在的规则只在一本书上调过，换书之后建议先标注几十句，看一下「准确率」页。

## 下一步建议

1. **标注同步到其他设备**：把 `dlg_<书ID>` 作为第二个文件存进 Drive 的 appDataFolder，复用现有的同步机制。
2. **用真实模型跑评测**：用 `--ollama` 分别测 qwen2.5:7b、qwen3:8b 等模型。如果「model on context」比规则·上下文（89%）低，就让模型只复核推测和未知的句子。
3. **多本书验证**：再找 3–5 本不同写作风格的小说，各标注 100 句左右。
